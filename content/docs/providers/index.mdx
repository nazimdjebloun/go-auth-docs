# Providers

go-auth includes built-in OAuth 2.1 providers for login, registration, account linking, and unlinking. Providers are optional — register them via `WithProvider` to enable OAuth routes.

## Setup

Register a provider:

```go
import "github.com/nazimdjebloun/go-auth/providers/github"

goauth.WithProvider(github.New(github.Config{
    ClientID:     os.Getenv("GITHUB_CLIENT_ID"),
    ClientSecret: os.Getenv("GITHUB_CLIENT_SECRET"),
    RedirectURL:  "https://myapp.com/auth/oauth/github/callback",
}))
```

Each provider requires:

- `ClientID` — The OAuth client ID from the provider.
- `ClientSecret` — The OAuth client secret from the provider.
- `RedirectURL` — The callback URL registered with the provider.

## OAuth flow

1. User clicks "Login with GitHub" → redirected to `GET /auth/oauth/github`.
2. Provider redirects back to `GET /auth/oauth/github/callback` with a code.
3. Library exchanges the code for an access token, fetches user info.
4. If the user exists (by email), they are logged in. If not, a new account is created (when `EnableOAuth` is true).
5. User is redirected to the frontend with a session token.

## Account linking

Authenticated users can link additional OAuth providers via `POST /auth/oauth/link`:

```json
{
  "provider": "github"
}
```

This redirects to the provider's authorization URL. After authorization, the provider is linked to the current user's account.

## Account unlinking

Authenticated users can unlink OAuth providers via `POST /auth/oauth/unlink`:

```json
{
  "provider": "github"
}
```

The library prevents unlinking the only authentication method — if a user has no password and no other linked provider, unlinking is rejected.

## Provider behavior

- **Production** — Providers are stateless. No OAuth state is written to the database.
- **Email matching** — OAuth users are matched by email. If the email exists, the provider is linked. If not, a new account is created (when `EnableOAuth` is true).
- **Password** — OAuth-only users have no `password_hash`. They can set one later via `POST /auth/set-password`.
