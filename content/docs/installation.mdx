# Installation

## Prerequisites

- **Go 1.22** or later (see `go.mod` in the source repo).
- A supported database: **SQLite** (via `modernc.org/sqlite` — no CGo required) or **PostgreSQL** (via `github.com/jackc/pgx/v5`).

## Supported databases

go-auth officially supports:

- **SQLite** — via `modernc.org/sqlite`, the pure-Go SQLite driver. No CGo required.
- **PostgreSQL** — via `github.com/jackc/pgx/v5`. The recommended driver for production.

Other databases may work via custom `Port` implementations but are not officially supported.

## Getting go-auth

```bash
go get github.com/nazimdjebloun/go-auth@latest
```

Use standard `go get` — no special install step is needed.

## Optional: CLI for local development

The `cmd/goauth` CLI is optional. It scaffolds a local database with realistic test data for development — it starts no servers.

```bash
go run github.com/nazimdjebloun/go-auth/cmd/goauth@latest --help
```

```bash
# Initialize a new database with default settings
go run github.com/nazimdjebloun/go-auth/cmd/goauth init

# Create a new admin user
go run github.com/nazimdjebloun/go-auth/cmd/goauth admin --email admin@example.com
```

For the full configuration reference, see [Configuration](./configuration.mdx).

## What this guide does not cover

This guide assumes a single-developer or proof-of-concept setup. For production deployment, you'll also need:

- **HTTPS termination** — reverse proxy (nginx, Caddy, Traefik) or cloud load balancer.
- **Secure cookie handling** — already handled by go-auth when `BaseURL` is `https://` (Secure is `true` by default).
- **CORS middleware** — if your frontend is on a different domain.
- **Logging middleware** — go-auth uses `slog`; integrate with your existing logger.
- **Rate limiting middleware** — go-auth includes built-in rate limiting for auth routes. See [Configuration](./configuration.mdx#withratelimit-and-its-narrower-variants--optional-on-by-default).
