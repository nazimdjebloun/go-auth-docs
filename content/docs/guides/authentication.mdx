# Authentication

go-auth supports email/password authentication with optional peppered passwords, email verification, and password reset flows.

## Registration

Users register via `POST /auth/register` with an email and password. The password is validated against the configured `PasswordPolicy` and hashed with the current hasher.

When `RequireEmailVerification` is true, the user receives a verification code by email and their `email_verified` flag stays `false` until they complete `POST /auth/verify-email`.

When `RequireEmail2FA` is true, the user is logged in with a pending 2FA session and must complete `POST /auth/2fa/verify` before accessing authenticated resources.

## Login

Users login via `POST /auth/login` with an email and password. The password is checked against the stored hash using the configured hasher.

When 2FA is required (either because the user has it enabled or because `RequireEmail2FA` is true), the response includes `pending_2fa: true` and a short-lived session token. The user must complete `POST /auth/2fa/verify` with the code sent to their email.

When 2FA is not required, the response includes a session token and the user is fully authenticated.

## Email verification

Email verification codes are sent on registration and can be resent via `POST /auth/resend-verification`. Resends are throttled — if the resend interval has not elapsed, the response includes `codeSent: false`.

Codes expire after `VerificationCodeTTL` (default 15 minutes).

## Password reset

The password reset flow:

1. `POST /auth/forgot-password` with the user's email.
2. The user receives a reset code by email.
3. `POST /auth/reset-password` with the email, code, and new password.
4. All other sessions for that user are terminated.

## Password change

Authenticated users can change their password via the session. The old password is required.

## Peer comparison

When enabled, peer comparison compares new user data against existing users' data and rejects requests with similar attributes. This prevents account impersonation through similar-looking emails or usernames.

## Similar-username lockout

When enabled, similar-username lockout prevents accounts with similar usernames from being created. This is disabled by default.
