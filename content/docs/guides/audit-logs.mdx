# Audit Logs

go-auth includes built-in audit logging for security-relevant events. Audit logs are append-only — they are created on events and never updated or deleted by the library.

## Setup

Enable audit logging with `WithAudit`:

```go
goauth.WithAudit(goauth.AuditConfig{
    Enabled:       true,
    FailureMode:   audit.AuditFailureOpen, // or audit.AuditFailureClosed
    RetentionDays: 90,                     // 0 = keep forever
    QueueSize:     1000,
    Workers:       3,
    BatchSize:     50,
    FlushInterval: 100 * time.Millisecond,
    Sinks:         []audit.EventSink{myKafkaSink},
})
```

Audit writes are asynchronous, fire-and-forget, and non-blocking. A failed audit write never fails the request — the error is logged at `ERROR` level and the request continues normally.

## What gets logged

Every security-relevant event is logged:

- Login (success and failure)
- Registration
- Password change and reset
- Email verification
- 2FA verification
- Session creation and termination
- OAuth login, linking, and unlinking
- Admin actions (user creation, deletion, role changes, password resets)
- Account deletion requests

Each audit log entry includes:

- `user_id` — the user who performed the action (null for system events)
- `action` — the event name (e.g. `login`, `register`, `password_reset`)
- `details` — arbitrary JSONB payload (e.g. `{"method": "password"}`)
- `ip_address` — client IP
- `user_agent` — client identification string
- `created_at` — when the event occurred

## Querying audit logs

Audit logs are accessible via:

- `GET /auth/audit/logs` — current user's logs
- `GET /auth/audit/logs/:id` — single log entry
- `GET /auth/admin/audit/logs` — all logs (admin only)
- `GET /auth/admin/audit/logs/:id` — single log entry (admin only)

## Retention

By default, audit logs are kept forever. Set `RetentionDays` to enable automatic cleanup:

```go
goauth.WithAudit(goauth.AuditConfig{
    Enabled:       true,
    RetentionDays: 90, // keep logs for 90 days
})
```

A background cleanup job runs periodically and deletes logs older than the retention period.

## Custom sinks

You can send audit events to external systems (Kafka, NATS, webhooks) by implementing the `audit.EventSink` interface:

```go
type EventSink interface {
    Send(ctx context.Context, event audit.Event) error
    Close() error
}
```

Register sinks via `WithAuditSink` or the `Sinks` field in `AuditConfig`.
