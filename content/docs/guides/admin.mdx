# Admin Guide

go-auth includes an optional admin surface for managing users, sessions, and audit logs. The admin surface is separate from the user surface — admin sessions are stored independently, and admin routes require admin permissions.

## Setup

Enable the admin surface with `WithAdmin`:

```go
goauth.WithAdmin(goauth.AdminConfig{
    Enabled: true,
})
```

By default, the admin surface is disabled outside development. When enabled, the admin user is created via the `cmd/goauth` CLI or the `POST /auth/admin/create-user` route.

## Admin login

The `POST /auth/admin/login` route unconditionally requires a second factor when email 2FA is available, even if `RequireEmail2FA` is false for normal users. The code is always sent. Admin two-factor is disabled outside development by default.

The admin login flow:

1. `POST /auth/admin/login` with email and password.
2. If 2FA is available, the response includes `pending_2fa: true` and a session token.
3. `POST /auth/admin/2fa/verify` with the code from the email.
4. The admin session is fully authenticated.

All invalid password or 2FA attempts on the same email address increment the same `failed_login_attempts` counter. Exceeding `MaxFailedLogins` locks the account — the lock is shared across login routes, and a 403 from admin login uses the same lockout event as a normal login. No other account is affected. The lockout expires after `LockoutDuration` (default 15 minutes).

## Admin sessions

Admin sessions are stored in the `admin_sessions` table, separate from user sessions. Admin sessions are managed via:

- `GET /auth/admin/sessions` — list all active sessions
- `DELETE /auth/admin/sessions/:id` — terminate a specific session
- `POST /auth/admin/sessions/bulk-delete` — terminate multiple sessions at once

## User management

Admin routes for user management:

- `GET /auth/admin/users` — list all users
- `POST /auth/admin/create-user` — create a new user
- `DELETE /auth/admin/users/:id` — delete a user
- `PUT /auth/admin/users/:id/role` — change a user's role
- `POST /auth/admin/reset-user-password` — reset a user's password

All user management routes require appropriate permissions (`user:read`, `user:create`, `user:delete`, `user:update`).

## Admin audit logs

Admin routes for audit log access:

- `GET /auth/admin/audit/logs` — list all audit logs
- `GET /auth/admin/audit/logs/:id` — get a single audit log entry

These routes require `audit_log:read` permission.
