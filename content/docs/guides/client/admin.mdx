# Admin Client

The admin client integration follows the same patterns as the user client, but uses separate admin sessions and routes.

## Admin login

Admin login uses `POST /auth/admin/login` with a separate session scope:

```javascript
const response = await fetch('/auth/admin/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'admin@example.com', password: 'password' }),
  credentials: 'include'
});

const data = await response.json();
if (data.pending_2fa) {
  // Admin 2FA verification required
} else {
  // Admin login successful
}
```

## Admin session cookie

Admin sessions use a separate cookie (`_admin_session`). Include it in subsequent admin requests:

```javascript
// List all users
const response = await fetch('/auth/admin/users', {
  credentials: 'include'
});
const users = await response.json();
```

## Admin routes

All admin routes require an admin session and appropriate permissions:

- `POST /auth/admin/login` — admin login
- `POST /auth/admin/logout` — admin logout
- `GET /auth/admin/me` — admin profile
- `GET /auth/admin/users` — list users
- `POST /auth/admin/create-user` — create user
- `DELETE /auth/admin/users/:id` — delete user
- `PUT /auth/admin/users/:id/role` — change user role
- `POST /auth/admin/reset-user-password` — reset user password
- `GET /auth/admin/sessions` — list all sessions
- `DELETE /auth/admin/sessions/:id` — terminate session
- `POST /auth/admin/sessions/bulk-delete` — terminate multiple sessions
- `GET /auth/admin/audit/logs` — list audit logs
- `GET /auth/admin/audit/logs/:id` — get audit log
