# Security Guide

This guide covers production security considerations beyond the default configuration.

## Deployment checklist

Before going to production, verify:

1. **HTTPS** — `BaseURL` must be `https://`. Cookies are `Secure` by default when `BaseURL` is `https://`.
2. **CORS** — Configure `AllowedOrigins` with your actual frontend domain. Never use `"*"`.
3. **Secret** — Use a strong, random secret (32+ bytes). Source from environment variables.
4. **Mailer** — Configure a real mailer for email verification, password reset, and 2FA.
5. **Rate limiting** — The built-in rate limiter is on by default. Consider infrastructure rate limiting as well.
6. **Audit logging** — Enable `WithAudit` for security-relevant events.
7. **Password policy** — Configure `PasswordPolicy` to meet your security requirements.
8. **Session limits** — Configure `SessionConfig` appropriate for your use case.

## CORS configuration

Configure CORS middleware before the auth handler:

```go
corsMiddleware := cors.New(cors.Options{
    AllowedOrigins:   []string{"https://myapp.com"},
    AllowedMethods:   []string{"GET", "POST", "PUT", "DELETE"},
    AllowedHeaders:   []string{"Content-Type", "Authorization", "X-CSRF-Token"},
    AllowCredentials: true,
})
```

## Cookie security

Cookies are secure by default:

- `Secure: true` when `BaseURL` is `https://`
- `SameSite: Lax` by default
- `HttpOnly: true` for session cookies

See [Configuration → WithCookie](../configuration.mdx#withcookie--optional) for the full resolution table.

## Session security

- Sessions are absolute, not sliding
- Token rotation on every refresh
- Per-user session limits
- Idle timeout

See [Security](../security.mdx) for the full session security model.
