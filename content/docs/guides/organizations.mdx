# Organizations

go-auth includes optional multi-tenant organization support. Organizations allow users to belong to multiple teams or tenants, each with their own members, roles, and audit logs.

## Setup

Enable organizations with `WithOrganizations`:

```go
goauth.WithOrganizations(goauth.OrganizationConfig{
    Enable:         true,
    MaxOrgsPerUser: 10,                 // optional, default 0 (built-in cap of 100)
    InviteTTL:      7 * 24 * time.Hour, // optional, default 7d
})
```

When `Enable` is false, no organization routes are mounted and the organization tables are not created.

## Organization roles

Each member has one of three roles:

- **owner** — full control. Can delete the organization, manage all members, and transfer ownership.
- **admin** — can manage members, invites, and settings. Cannot delete the organization.
- **member** — basic access. Can view organization data and manage their own membership.

## Creating organizations

Users create organizations via `POST /auth/org`. The creator becomes the owner.

```json
{
  "name": "My Organization",
  "slug": "my-org"
}
```

## Inviting members

Owners and admins can invite users via `POST /auth/org/:id/invite`:

```json
{
  "email": "invitee@example.com",
  "role": "member"
}
```

The invitee receives an email with a link to accept the invitation. Invitations expire after `InviteTTL`.

## Accepting invitations

Users accept invitations via `POST /auth/org/accept-invite`:

```json
{
  "token": "invite-token"
}
```

## Managing members

- `GET /auth/org/:id/members` — list all members
- `PUT /auth/org/:id/members/:userId/role` — change a member's role
- `DELETE /auth/org/:id/members/:userId` — remove a member

## Organization audit logs

Organization-scoped audit events are stored in the `organization_audit_logs` table. These are separate from the global audit logs and track organization-specific actions.
