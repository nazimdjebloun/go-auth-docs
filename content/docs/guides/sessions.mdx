# Sessions

go-auth manages sessions with absolute TTLs, idle timeouts, and token rotation. Sessions are stored in the database and managed via the `Auth` API or the HTTP handler.

## Session lifecycle

1. **Creation** — A session is created on login, registration, or OAuth callback.
2. **Active** — The session is active and can access authenticated resources.
3. **Refresh** — The session token can be refreshed via `POST /auth/refresh` or `POST /auth/refresh-session`.
4. **Expiry** — The session expires when its TTL or idle timeout is reached.
5. **Termination** — The session is terminated on logout, token revocation, or admin action.

## Token refresh

Sessions have two tokens:

- **Session token** — The primary bearer token. Used for authentication.
- **Refresh token** — Used to obtain a new session token without re-authenticating.

Refresh tokens are rotated on every use. The previous refresh token is still accepted during the `GraceWindow` (default 5s) so two in-flight refreshes don't log the user out.

## Multi-session support

Users can have multiple active sessions simultaneously. Each session is independent — terminating one session does not affect others.

List all sessions: `GET /auth/sessions`
Terminate a specific session: `DELETE /auth/sessions/:id`
Terminate all sessions: `POST /auth/end-all-sessions`

## Session limits

Configure per-user session limits:

```go
goauth.WithSession(goauth.SessionConfig{
    MaxLifetime: 30 * 24 * time.Hour, // optional, default 0 (no limit)
})
```

When the limit is reached, the oldest session is terminated automatically.
